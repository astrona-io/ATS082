# Summary

No single number describes developer productivity. Any one measure can be pushed up while the real result gets worse, and a measure used as a target changes the behaviour it was meant to describe.

The SPACE framework names five dimensions: satisfaction and well-being, performance, activity, communication and collaboration, and efficiency and flow. A good set takes measures from several dimensions and mixes workflow measures, which come from systems, with perceptual measures, which come from asking people.

The DevEx framework names three areas of the daily experience: feedback loops, cognitive load and flow state. A platform acts on each: fast pipelines for feedback, templates and catalogues for load, and self-service for flow. Each area needs both a perceptual and a workflow measure.

Cognitive load cannot be read from a log. A team measures its causes, such as steps, tools, handoffs and time to first deployment, and asks about effort in a survey that stays the same between rounds. Measures that move together show where to look, and conversations with the teams explain why.

A balanced set has few metrics, covers several dimensions, includes at least one perceptual measure, pairs a measure that can be pushed with a measure that shows harm, and reports at the level of a team. Individual activity counts are left out because people game them and lose trust in the data.

Key facts:

- SPACE has five dimensions; DevEx has three areas.
- A workflow measure comes from systems and a perceptual measure from people.
- Deployments per day is paired with the change fail rate.
- Each metric in a set supports a stated decision.
