# Developer Experience Evidence And Incentives

This module explains how a platform team combines numbers and user feedback to judge a platform change. It covers the dimensions of developer productivity, the difference between quantitative and qualitative evidence, the way a measure changes behaviour once people are judged by it, and the limits of before-and-after comparisons. The hands-on part uses usage counts, support tickets and survey answers in a kind cluster.

## Learning Goals

- Name the five dimensions of the SPACE framework and explain why one activity measure is not a productivity score.
- Explain what quantitative evidence and qualitative evidence each show and miss.
- Normalise a count by a denominator, for example tickets per 100 sessions, and read it together with a completion rate.
- Explain how a measure used as a target is gamed, and how a single metric can reward the wrong behaviour.
- Identify a confounding change and state what a before-and-after comparison can and cannot show.

## Before You Start

You should know what a ConfigMap is and how to read JSON with `jq`. The playground holds usage numbers, survey answers and a change log in ConfigMaps. Technical terms are defined where they first appear.
